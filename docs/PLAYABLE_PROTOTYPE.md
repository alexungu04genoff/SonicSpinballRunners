# Two-Zone playable prototype

Each Act now has a mandatory **goal ring**. It starts gray and turns gold when the Act score target is met. Touch it to choose a Buddy and transfer safely to the next Act's spawn; the sixth ring ends the run. The former activation line no longer advances the prototype. Existing Acts default the ring to spawn. In the Act editor, use **Place / move goal ring** and **Goal diameter** (one cell by default). Drag or arrow keys move it; resizing and placement support undo/redo. Delete restores the default, so an Act always retains its goal. Saving writes format 16; older files load without being rewritten.

The original white ball-contact circle remains visible. A green ×2 timer drains over white; yellow ×3 drains over green; red ×4 drains over yellow. Expiry drops one tier at a time. Only ×2 and higher show text, colored to match. Multiplier, score popups, goal captions and on-table labels share the former 23-point multiplier font enlarged by 20%. The new goal is lightweight runtime hardware; terrain and scenery still use validated offline bakes.

Goal/meter verification (2026-10-30): 15 goal/editor/decay checks, 170 lifecycle checks, 32 scoring-authoring checks, 37 playlist checks, 29 existing Scorecraft checks, 113 rendered six-Act run checks, 54 packaged retry/budget checks, 16 packaged feedback checks and 40 package/bake checks passed. Editor placement/size and runtime gray/gold goals, stacked colors and widescreen text were visually reviewed. All 12 Act/theme variants were rebuilt; no authored source files were rewritten.

The ball carries a live combo indicator from ×2 through ×4; ×1 has no text. Accepted scoring hits show brief floating point totals at the bumper, ring pickup or authored mechanic, with ball position as the fallback for aggregate feature awards. Totals already include special and Buddy bonuses; fixed feature awards retain their existing scoring rules. Nearby rapid awards of the same kind combine their exact totals, and at most 12 popups remain visible for less than a second. Pause hides and freezes this feedback; Act transfers, drains and results clear it. This screen-space overlay does not affect physics, scoring calculations, baked geometry or input.

Score feedback verified on 2026-10-30: 15/15 rendered feedback checks, 113/113 packaged session checks, 40/40 package checks, 29/29 existing Scorecraft checks and 13/13 Buddy scoring checks. Captures at 1280×720 and 1920×810 confirm the overlay stays aligned with the ball and scoring positions. Text size, popup density and fade timing remain human playtest tuning.

Protected transfers verified on 2026-10-30: rendered source and packaged sessions passed 113/113 checks; drain/retry suites passed 54/54, including a real drain-zone crossing, automatic relaunch, pause and cancellation. The refreshed Windows package passed 40/40 bake checks across all 12 Act/theme variants. Rendered hover, shrink and reappearance captures were reviewed. Normal play loaded baked geometry without runtime rebuilds; existing GPU warm-up stalls remain possible.

Menu panels hide immediately and use deferred deletion so button signal emitters survive their callbacks. The session regression now triggers the actual Start, Resume, Buddy, Play again, Restart and Return to menu signals; the rendered source run passed 108 checks with no engine errors on 2026-10-30. Earlier direct transition calls did not cover the panel-deletion crash.

The prototype camera uses zoom 1.3 and a vertical target 55% down the screen. The compact HUD uses 18/16-point headings/body text and a 35%-opaque backing; control instructions remain in the menu instead of covering gameplay. Window resizing and F11 fullscreen expand to the display aspect ratio, including ultrawide, instead of letterboxing the original canvas. Rendered checks covered 1600×900, 1920×810 and native 1920×1200 fullscreen on 2026-10-30.

Run **Sonic Spinball Runners.exe** from the Windows build. No Godot installation or repository is required for that build. In the source checkout, run **Play Prototype.cmd** with Godot 4.7.2 installed; it prepares missing bakes on first launch. Run **Bake Prototype.cmd** after changing the Acts or presentation sources.

Choose Sonic, Tails, Knuckles or Shadow, then start the run. **Green Hill** contains three Acts with provisional targets of **1,000, 1,500 and 2,000**. **Chemical Plant** follows with three more Acts targeting **2,500, 3,000 and 3,500**. Reaching a target colors that Act's goal ring; touch the ring to advance. Beginning the next Act resets local score while preserving cumulative score and Buddies. The sixth goal ends the run and shows results for both Zones.

Every start, replay or restart draws a fresh random order from the `.tres` files directly in `data/acts/Authored/`, with no repeated Act within the six-Act run. The current pool contains First Try Smooth Decor, RampMania, Reverse C Spring, Second Simple, Secret Entry and SpringUp, so all six appear once. If more Acts are added, six are selected without replacement; fewer than six or incompatible connectors produce a startup error. The two themes retain their fixed order. The seed appears in pause and results; launch Godot with `-- --seed=18` to reproduce a particular order for debugging.

Challenge starts every Act with **three balls, including the ball in play**. Drains and manual retries spend one ball while preserving earned points, open score exits and the acquired build. Losing the third ball ends the run. Clearing an Act refreshes the next Act's budget to three. Retrying before launch or during an existing respawn cannot consume another ball. Practice mode keeps unlimited retries and separate records. Restarting clears all score, Buddy and budget progress.

After touching each nonfinal unlocked goal, choose a Buddy, for five drafts in a complete run. Gameplay pauses for the choice, then Sonic floats smoothly to the next Act's authored spawn over 1.25 seconds, including at the Zone boundary. The catalogue remains small so the prototype can test distinct scoring routes:

| Buddy | Level 1 bonus | Level 2 bonus |
| --- | --- | --- |
| Ring Scout | +10 per ring | +20 per ring |
| Bumper Coach | +75 per bumper award | +150 per bumper award |
| Feature Fox | +250 per completed rack, switch bank, spinner goal or lane set | +500 per completion |

Picking an owned Buddy upgrades it to level two; fully upgraded Buddies leave the available choices. At least one choice remains through all five drafts. Bonuses are flat additions after existing combo/special scoring and do not add combo links, timer refreshes or special charge. They never pay for zero-point sources or ordinary spinner ticks. The HUD shows the current build and included Buddy bonus; success and failure results show each Buddy's contribution, a scrollable Act breakdown and ordinary scoring. Amounts and the three-ball budget are provisional. Shops, bosses, more Buddy effects and permanent progression remain future work.

At the bottom of the drain zone, the ball stops immediately, shrinks away, and grows back at the current spawn. Manual retries use the same animation. During either transfer, the ball cannot collide, score or accept gameplay input. Arrival restores those systems and launches from rest after 0.35 seconds. Pause freezes the transfer; returning to the menu or restarting safely cancels it. A final Challenge loss stops the ball and shows results without another respawn. Transfer timing and camera feel still need human playtesting.

The menu saves character choice, Practice preference, sound preference, best completed score and fastest completion time in Godot's user-data folder. Two-Zone Challenge and Practice records are separate from each other and from the earlier three-Act records, which remain preserved in the settings file. Failed runs do not replace completion records. Pause provides resume, restart, menu and quit. Short synthesized cues identify scoring, feature completion, exit unlocks, Act changes and drains.

The source Acts stay unchanged: run-local targets and goal hardware are applied to the streamed instances. Their source fingerprints and bake validation remain authoritative. Existing standalone Act play, editor workflows and the published Endless roster retain their own rules. The old three scoring demonstration layouts remain in `data/prototype/` but are not selected by this run.

**All six Acts are baked in both themes**, because any Act can occupy either Zone: 12 Act variants plus two shared theme bakes. `Bake Prototype.cmd` uses the same roster as the run. The launcher also prepares missing bakes or Acts saved after their last bake; run the explicit bake command after presentation changes. Normal play loads the baked collisions, visual recipes, optimized mesh batches and warm-up metadata. The existing loader rejects stale bakes instead of rebuilding geometry during gameplay. GPU uploads and driver shader compilation still happen at runtime; offline bakes do not eliminate every first-launch or streaming stall.

## Source verification and Windows export

`tests/prototype_plan_regression.gd` checks folder discovery, seeded shuffling, no repeats, connector alignment, source preservation and all five draft opportunities. The deterministic session check is `tests/prototype_run_regression.gd`. It tests the real menu and streaming lifecycle, injects awards to isolate scoring transitions, and verifies both Zones, locked goals, drafts, pause, checkpoint persistence, final results and clean replay. Normal baked runs also assert zero runtime rebuilds and use of both theme bakes. `tests/prototype_budget_regression.gd` covers retry input, finite failure, duplicate drain protection, contribution accounting and Practice isolation. `tests/buddy_scoring_regression.gd` checks bonus ordering and upgrade/reset behavior. The input-only `tests/prototype_route_probe.gd` remains a limited steering heuristic, not proof that every authored route is beatable. Human testing is needed for the six-Act score curve, flipper timing, camera readability, character balance and sound comfort.

Export with `tools/export_prototype.ps1 -WindowsTemplate <path-to-matching-Windows-release-template>`. The script creates a separate source snapshot, imports it, bakes every authored Act in both themes, exports an embedded Windows executable and creates a zip under `test-results/prototype-build/`. It does not download a template or publish a release. Use a template matching the installed Godot version, since baked validation includes the engine version. Logs stay beside the snapshot.

The snapshot enables a small export plugin that retains source PNGs alongside imported textures. This preserves existing bake fingerprints instead of bypassing runtime validation. Before creating the zip, the exporter runs `tests/prototype_package_regression.gd` against the executable's embedded resources to check the menu entry point, authored-folder discovery, both themes and every Act/theme combination, including validated collisions and warm-up metadata.
