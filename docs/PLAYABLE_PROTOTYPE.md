## Automatic run archive and run feel

Prototype automatically archives one JSON per run in `user://telemetry/runs/`. On Windows with the default profile this resolves to `%APPDATA%\Godot\app_userdata\Sonic Spinball Runners\telemetry\runs`. Results retain **Copy run data**, show save status, and offer **Open telemetry folder**. No administrator permissions, repository writes, uploads or automatic retention deletion are involved.

Wins and out-of-Balls losses save immediately. Return to menu during play archives a partial run and opens **Run abandoned** Results, where the player can add feedback before returning to the menu. Restart and explicit Quit also archive partial progress without a blocking prompt. Forced process termination or power loss cannot guarantee a save. A run abandoned during startup records `started: false` with no fabricated played Acts; abandoning a Buddy draft does not duplicate its already-cleared Act.

The empty-by-default **Run feel** textbox is exported as `run_feel`. Notes autosave after a short typing pause and flush on Copy, replay, menu exit and Quit. Edits update only that run's existing JSON, with no extra archive copies. Each note replacement verifies that the existing file still matches the session's previous write, so external edits are not silently overwritten.

Disk and clipboard use the same cached exported object and JSON. Each archive includes local end time, `won`, `completed`, `termination_reason` (`completed`, `out_of_balls`, `returned_to_menu`, `restarted` or `quit`), character, mode, seed, effective configuration, planned course and played-Act telemetry. `completed` means all configured Acts were cleared; an abandoned run is distinguished from a loss by its termination reason. Filenames contain timestamp, seed, mode and outcome, with numeric suffixes on collisions. Temporary writes are flushed and verified before same-directory publication; failures leave Results and Copy usable and report a concise warning.

`tests/prototype_archive_regression.gd` exercises real runs, partial exits, feedback autosave, exact disk/clipboard equality, collision handling, external-edit protection and an intentionally failed write. Its temporary data is isolated under `telemetry/runs/_validation` and cleaned up by the fixture.

Choose a character, Practice and sound, then configure **1–7 Zones**, the theme pool and the production Act pool. Each Zone contains **3 distinct Acts**, giving 3–21 Acts per run. Fresh settings and Reset run setup select **2 Zones, Green Hill + Chemical Plant, and all valid Acts in `res://data/acts/Authored`**. Start requires at least one theme, three Acts and valid existing baked data. Select all / Select none never silently restore defaults. The Act list shows authored titles and source filenames.

Targets remain **1000 + 500 × zero-based global Act index**: the default six-Act run keeps **1,000 / 1,500 / 2,000 / 2,500 / 3,000 / 3,500**; Act 21 targets 11,000. Reaching a target colors the Goal Ring; touching it advances. Each new Act resets local score while preserving total score and Buddies. The final configured Goal Ring ends the run. Scoring, combos and physics are unchanged by run setup.

Every start, replay or restart draws a fresh seed. The same seed and configuration reproduce the same course. Sorted theme IDs feed seeded shuffle bags; each bag uses every selected theme once and avoids adjacent repeats across bags when possible. Each Zone chooses three different Acts, preferring the least-used eligible sources with seeded ties. Source paths are sorted before randomization, and the previous Act is excluded at Zone boundaries. Acts may repeat between Zones and can use any selected theme. The seed appears in pause and results; launch Godot with `-- --seed=18` for debugging.

Run setup persists in `prototype_settings.cfg`. Themes store explicit selected IDs; Acts store explicit deselected paths, so new valid production Acts default selected and removed sources are ignored. Reset restores the fresh defaults. Copied run JSON includes `run_configuration` (Zone count, three Acts per Zone, selected theme IDs and Act paths), a deterministic configuration fingerprint and the complete planned `course`. Played Act telemetry retains actual Zone, Act, theme, source and target. Standalone Endless is unaffected.

Challenge starts each Act with a **base of three balls, including the ball in play**, adjusted by Buddies. Dark Chaos subtracts one (at either level, minimum one); RC Tornado adds one for the upcoming Act only. Drains and manual retries spend one ball while preserving earned points and the build. Chip can rescue one final-Ball loss per run. Clearing an Act refreshes its budget. Duplicate retry/respawn requests cannot spend another Ball. Practice keeps unlimited retries, ignores the Dark Chaos penalty and has separate records. Restarting clears run state.

After each nonfinal physical Goal Ring, choose from three deterministic valid Adventure Buddies, for one draft between every pair of Acts. The seed and draft number reproduce offers; refresh cannot reroll them. The eleven-entry catalogue is Chip, Dark Chao, Dark Chaos, Hero Chaos, Knuckles Omochao, RC Tornado, RC UFO, Sonic Omochao, Tails Omochao, Wizard Chao and Yacker. Cards use local, aspect-preserved Sonic Runners Adventure portraits. The old Ice/Spring/Magnet Chao Lab is retired; it is unrelated to these Buddies.

The cap is five unique persistent Buddies. Owned upgradeable entries offer their next level; maxed entries are excluded. RC Tornado uses no slot and is offered only once per run. Chip is level one only. Fewer than three valid entries produces every remaining choice. The draft pauses gameplay, then transfers the Ball to the next spawn over 1.25 seconds.

Buddy percentages independently add to the normal completed Scorecraft award, without Buddy multiplication, combo links, timer refresh or Special charge. Physics effects use the existing modifier resolver. Virtual Rings use a counter-only path and cannot recurse. HUD/results preserve the acquired build, Chip rescue status, individual score contributions and Act breakdown. See [exact adapted effects, draft lifecycle, ring pacing and Buzz Bomber](ADVENTURE_BUDDIES_AND_BUZZ.md) and [temporary art sources](TEMP_ASSET_SOURCES.md). Tuning remains provisional; shops, bosses and permanent progression remain future work.

At the bottom of the drain zone, the ball stops immediately, shrinks away, and grows back at the current spawn. Manual retries use the same animation. During either transfer, the ball cannot collide, score or accept gameplay input. Arrival restores those systems and launches from rest after 0.35 seconds. Pause freezes the transfer; returning to the menu or restarting safely cancels it. A final Challenge loss stops the ball and shows results without another respawn. Export with `tools/export_prototype.ps1 -WindowsTemplate <path-to-matching-Windows-release-template>`. The script creates a separate source snapshot, imports it, bakes every authored Act in all registered themes, exports an embedded Windows executable and creates a zip under `test-results/prototype-build/`. It does not download a template or publish a release. Use a template matching the installed Godot version, since baked validation includes the engine version. Logs stay beside the snapshot.

The snapshot enables a small export plugin that retains source PNGs alongside imported textures. This preserves existing bake fingerprints instead of bypassing runtime validation. Before creating the zip, the exporter runs `tests/prototype_package_regression.gd` against the executable's embedded resources to check the menu entry point, authored-folder discovery, all registered themes and every Act/theme combination, including validated collisions and warm-up metadata.
